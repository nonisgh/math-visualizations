# 球面さんぽ macOS 版（実験）

ウェブ版 `~/math-visualizations/s3walk.html` の「中にいる人の景色」を、Swift（SwiftUI ＋ MTKView）と Metal で作り直したもの。
ウェブ版は書きかえていない。Xcode が無くても（Command Line Tools だけで）作れる。GitHub には上げていない。

- 第 1 歩（2026-10-26）：中の景色・球層の型（球層・8 つの極の玉・赤道の膜・もや）
- 第 2 歩（2026-10-26）：4K・60fps、軽い線、足あと・目印を置く・縦横無尽・赤道や極を通った知らせ、設定のパネル、続きから開く
- 第 3 歩（2026-10-26）：S³ の地図（並べる・浮かせる）、Mac らしい画面（ツールバー・インスペクター・メニュー）
- 第 4 歩（2026-10-26）：地図を 2 枚（ウェブ版の真ん中と左上）、矢印の軸、光る線（にじみ＋EDR）、ゲームコントローラー、トラックパッドの触覚
- 第 5 歩（2026-10-26）：絵の目印・色の点（P）、魚眼・360° レンズ、管（経線・赤道の輪・120 胞体の部屋の辺）、S² の仲間の窓、螺旋・回る輪、コントローラーの反転とゲームのような操作

## 作る・開く

```bash
cd ~/math-visualizations/macos/S3Walk && ./make-app.sh && open S3Walk.app
```

- `./make-app.sh`：`swift build -c release` して `S3Walk.app` に包む（Dock に置ける）
- シェーダーは `Sources/S3Walk/Shaders.swift` の文字列で、起動の時に組み立てる（Xcode の metal コンパイラが要らないように）
- 設定・いる場所と向き・置いた目印は、閉じても残る（UserDefaults `io.github.nonisgh.s3walk`）

## 線の見え方：やわらか（標準）／くっきり（2026-10-26、ウェブ版にも）

ユーザー「前のはやっぱり現実を探索してる感じ、遠近感がよくわかる。以前のを標準に」→ **やわらか**（殻の上で決まった角度の太さ。近い線ほど太くやわらか、遠い線ほど細い）を標準に、
**くっきり**は別のモードに。切りかえは C キー（Mac 版・ウェブ版とも）、Mac 版はインスペクターの「線の見え方」、ウェブ版は「線の見え方：やわらか／くっきり」のボタン（S.lineMode）。
やわらかの絵は、前とまったく同じ（ウェブ版で画素のちがい 0）。

### くっきりの作り

球層の網目・軽い線・赤道の膜は、殻の上で決まった角度の太さで描いていたので、すぐそばの殻の線が画面いっぱいの太い帯になってぼやけていた（ユーザー「球殻のぼやけ具合がすごくて視認性わるい」）。
「線の太さ（画素）」（くっきりの時、既定 1.8）で、芯の太さを画面の画素で決めるようにした：1 画素が殻の上で占める角度（道のり t・光が面に当たる角・殻の半径から）を使い、
近い線は細くくっきり、1 画素より細い遠い線はそのぶん薄く。目印の玉のふちも 1 画素ぶんだけなめらかに。すぐそばの殻の面も少し薄く（線は残す）。
ウェブ版 s3walk.html にも同じもの（「線の太さ」スライダー、S.lineW）。Mac 版とウェブ版の絵は画素で一致（`refs/web_crisp_*.txt`、ちがい最大 1）。

## 第 5 歩で移したもの

- **目印の見せ方**（P、ウェブ版と同じキー）：玉 → 絵（絵文字の玉。見る人の方を向き、右上に赤い点）→ 色の点 → なし。絵・色の点の時は玉を 1.5・1.9 倍、線は「線の濃さ」で薄く。
  「遠回りの像を、絵の裏から見た形に」も。地図では絵文字の札。ウェブ版と比べて、絵の玉のまわりの色のちがいは 0〜255 で 1.3 以内（絵文字の描き方の差）
- **レンズ**：ふつう・魚眼（等距離射影、視野 360° まで）・360°（正距円筒）。ウェブ版と画素で一致（ちがい最大 1）
- **管**：経線・赤道の輪、120 胞体の部屋の辺（光を少しずつ進めて探す。重い）。ウェブ版と画素で一致（ちがい 0）。地図にも線
- **S² の仲間の窓**：同じ操作を、ふつうの球面 S² でした場合（ウェブ版の左の窓）。地図の上に並ぶ（地図 1 の右上のボタンかインスペクターで出し入れ）
- **決まった道**（インスペクターの「歩く」）：螺旋（巻き数・傾き・歳差）、回る輪（軸 x・y・z・w・全部、1 周で回す角）。キーかスティックで歩くとやめる
- **コントローラー**：右スティックの左右・上下の反転。「ゲームのような操作」（既定 ON）：右スティックの左右で体の向き、上下は頭だけ（見上げても進む向きは水平のまま）、動き出し・止まりに慣性。Y で見ている向きへ進む

**見つけたこと：ウェブ版の 120 胞体の頂点がずれている**　`cellDodeca` の頂点 (0, ±1/φ, ±φ)… と面の向き (0, ±1, ±φ)… の組み合わせが合わず、
どの面にも頂点が 1 つしか乗らない。そのため `cell120().edges` が 3600 本・頂点 2153 個（正しくは 1200 本・600 個）になり、ウェブ版の地図の「部屋」の線がずれている。
中の景色の部屋（面の向きだけを使う）は正しい。Mac 版は頂点を (0, ±φ, ±1/φ)… にして直した（面はそのままなので、中の景色はウェブ版と同じ。`--verify` で辺 1200・頂点 600・辺の長さ 0.270919 を確かめる）。
2026-10-26、ウェブ版の s3walk.html と thurston.html（同じずれ。H³ の部屋も）も同じように直した（GitHub はまだ）。

## 4K・60fps

- 既定は **60 fps・画面の画素そのまま**（LG の全画面なら 4096×2304）。V で画面の速さ（144Hz）に切りかえられる
- 「足りない時だけ細かさを下げる」（既定 ON）：実際の fps が目標に 2 回（1 秒）続けて届かない時だけ 8 % ずつ粗く（最低 0.5）、2 秒続けて届いていれば 5 % ずつ細かく戻す。
  GPU の時間では決めない（軽いと Mac が GPU を遅くして、時間が長く見えるため。第 1 歩ではこれで細かさが下がりきり、さらに 120 fps 指定のため 144Hz の画面で 72 fps になっていた）

1 コマの GPU の時間（ミリ秒、M1 Max、`--bench4k`、120 コマ続けて流して 3 回のうち速い値）：

| 場面 | 3840×2160 | 4096×2304 | 4K・60fps |
|---|---:|---:|---|
| 球層（殻の見える距離 3、球層の海・既定） | 11.7 | 13.3 | そのまま |
| 球層（殻の見える距離 1、ウェブ版の既定） | 7.0 | 7.9 | そのまま |
| 球層・網目なし | 10.8 | 12.2 | そのまま |
| 球層・立体 | 14.7 | 17.3 | 細かさ 0.95 前後 |
| 球層＋軽い線 | 17.1 | 19.3 | 細かさ 0.9 前後 |
| 軽い線だけ（ウェブ版の既定の見え方） | 8.2 | 9.2 | そのまま |
| 球層なし（玉・膜・もや） | 2.9 | 3.3 | そのまま |

速くした工夫（絵は変えずに）：殻との当たりを三角関数なしで（cos(t−φ) ＝ w／amp）、殻の向きを式で（cv ＝ ±vt.w／√(1−w²)）、
見えないほど薄い殻を飛ばす（1/255 未満）、重ねる層の色を配列にためず重ねる時に計算（レジスタが減り全体が速く）。
4096×2304 の球層は 23 ms → 13.3 ms。ウェブ版（1920×1080 で 9.24 ms）の 4.6 倍の画素を、1.4 倍の時間で描ける。

## 確かめ（`S3Walk.app/Contents/MacOS/S3Walk --verify`、すべて合格）

- 計算：10 万歩でたらめに歩いても体の枠は正規直交（ずれ 7e-16）。1000 歩に分けた点は大円の式どおり。大円を 2π 歩くと点も右・上・前も元どおり
- 画面（Metal で描いた画素から、2001×2001・視野 70°）：アナ極から方位 30° へ s ＝ 0.3・0.7・1.0 歩き、東 +x の玉（半径 0.09）を見る
  - 見かけの大きさ：sin α ＝ sin r ／ |sin d| と 1 画素以内。近い道も遠回りの像も
  - 像の向き：玉の右上の赤い点が、近い道では右上、遠回りでは左下 ＝ 180° 回る（鏡なら左上か右下）
  - 立体の配置：玉の上と右に小さい玉を置くと、遠回りの像では上の玉が下に、右の玉は右のまま ＝ 裏側から見た形を 180° 回した像
  - 北極に立つと、南極の玉が空全体をおおう
- 歩く（アプリと同じ step を 1/60 秒ずつ）：1 周で 赤道 → カタ極 → 赤道 → アナ極 の順に知らせ、2π ＋ 0.305 歩くとアナ極から 0.305、
  足あとは 0.6 ごと・最大 40、目印の玉は 64 個まで、縦横無尽で 50 秒歩いても体の枠は正規直交・仰角 ±80° の中、保存して読み直すと同じ
- ウェブ版との比べ（`--webcmp`、429×537、32 画素おき 238 画素）：
  - 球層：ちがい最大 1（0〜255）
  - 球層＋軽い線：ちがい最大 3（同じ道のりの層の扱いをウェブ版に合わせた時。下の注）
  - 軽い線だけ：ウェブ版の式を Python で一から計算した色（`refs/lite_ref.py`）と、ちがい最大 4

**注：同じ道のりの層**　赤道の膜（w ＝ 0）と赤道の軽い線（w ＝ 0 の殻）は、光がちょうど同じ道のりで当たる。
ウェブ版は層を「前より道のりが大きいもの」で選ぶので、道のりがちょうど同じだと片方が抜ける（抜けるかどうかは丸めしだいで、画素ごとにばらばら。赤道の線が所々うすくなる）。
Mac 版は同じ道のりなら両方とも重ねる（`--webcmp` の時だけ `webTies` でウェブ版と同じ抜け方にして比べる）。
